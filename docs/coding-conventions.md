# 코딩 규약

이 문서는 저장소의 Python 샘플과 문서를 같은 방식으로 유지하기 위한 규칙입니다.

## TR 모듈

- TR 코드마다 하나의 모듈을 둡니다. 파일명은 TR 코드와 일치시킵니다. 예: `t2111.py`, `CFOAT00100.py`.
- 기능 상위 폴더는 `market_data/`, `orders/`처럼 구분하고, 실제 호출 모듈은 TR 이름을 유지합니다.
- 모듈은 `PATH`, `TR_CD` 상수를 정의하고, 입력을 해당 TR의 InBlock에 매핑합니다.
- 함수는 `LSClient`를 받아 TR을 호출하고 원본 응답을 `TRResponse`로 반환합니다. 응답 필드 정규화가 필요한 경우에는 별도 요구사항과 공식 명세를 확인합니다.
- 필수 입력을 호출 전에 검증합니다. 공식 가이드가 길이를 지정하면 잘못된 길이를 거부해 빈 데이터 응답을 정상 값으로 오해하지 않게 합니다.
- 주문 함수는 호출자가 전달한 주문 조건만 전송합니다. 시세 조회, 가격 산출, 자동 재시도, 주문 의사결정은 포함하지 않습니다.

## 인증정보와 로그

- 앱키, 시크릿, 접근토큰, 계좌번호는 소스·문서·로그에 기록하지 않습니다.
- 예제는 환경변수 또는 무시 처리된 로컬 `.env`에서 설정을 읽습니다.
- 예제의 출력은 필요한 응답 데이터만 보여주며 인증 헤더를 출력하지 않습니다.
- 주문은 계좌에 영향을 줄 수 있으므로 실행 전 종목·방향·가격·수량을 명시적으로 확인할 수 있게 합니다.

## 이름과 문서

- 함수와 변수는 `snake_case`, 상수는 `UPPER_SNAKE_CASE`, 모듈명은 공식 TR 코드 표기를 따릅니다.
- 공개 함수에는 한국어 docstring으로 목적과 주요 제약을 설명합니다.
- TR 필드명·자료형·길이는 공식 가이드 표기를 사용하고, 실서버에서 확인된 사실과 명세상 사실을 구분합니다.
- 새 TR을 추가하면 기능 문서와 API 목록의 구현/검증 상태도 함께 갱신합니다.
- REST와 WebSocket은 전송 방식별 클라이언트로 분리합니다. 실시간 시세는 필요한 TR만 명시적으로 허용하고, 실전 서버 접속은 명시 옵션으로 둡니다.

## 변경 관리

- 기능은 Codex, Claude, 운영/테스트 목적에 맞는 브랜치에서 작업하고, 검토 후 기준 브랜치에 반영합니다.
- API 호출이 주문을 발생시키는 작업은 코드 검토와 조회 전용 확인을 먼저 거칩니다.
- 저장소에 자동 테스트를 추가하거나 실행하는 것은 작업 범위에서 별도로 요청된 경우에만 합니다.
